---
name: api-zod manual edits
description: How to safely add fields to generated api-zod and api-client-react schemas when orval is not re-run
---

The lib/api-zod package is generated by orval but NOT regenerated on each change. When adding new fields to a response type (e.g. CalendarStatus, Trip):

## Three places to update (all three, atomically)

1. `lib/api-zod/src/generated/types/<TypeName>.ts` — TypeScript response interface in api-zod
2. `lib/api-zod/src/generated/api.ts` — Zod schema for the response (runtime validation)
3. **`lib/api-client-react/src/generated/api.schemas.ts`** — The FRONTEND's copy of the TypeScript interface (hand-maintained; NOT imported from api-zod)

After editing all three source files:
- Rebuild api-zod: `cd lib/api-zod && pnpm tsc --build`
- Rebuild api-client-react: `cd lib/api-client-react && pnpm tsc --build`
- The visitecrm frontend then picks up the updated types through project references

**Why:** `lib/api-client-react/src/generated/api.ts` imports types from `./api.schemas` (a local file), NOT from `@workspace/api-zod`. Fixing only api-zod leaves the frontend with stale types — confirmed when CalendarStatus `status` field addition to api-zod still caused TS2339 in configuracoes.tsx until api.schemas.ts was also updated.

**How to apply:** For response types, search for the type name in BOTH `lib/api-zod/src/generated/types/` AND `lib/api-client-react/src/generated/api.schemas.ts`. For trip body types: also update createTripBody.ts and updateTripBody.ts in api-zod.
